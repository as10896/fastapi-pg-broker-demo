Workers

A worker is a process: a replica of the worker compose service, like a celery worker. It runs several consumers, loops that claim a message, handle it, then ack or nack it. Workers only talk to Postgres and expose no ports.

Stop, kill, crash

Stop is graceful: the consumer finishes and acks its current message, then exits.

Kill simulates a consumer crashing mid-message: no ack, no nack, and its lease is no longer renewed. After {{ settings.visibility_timeout_s | round(1) }} s the reaper makes the message pending again. Use a long work time (e.g. 5000 ms) so there is time to click.

From the terminal

docker compose up -d --scale worker=3   # more worker processes
docker compose kill worker              # SIGKILL every worker: a real crash
docker compose up -d worker             # bring them back
docker compose logs -f worker
